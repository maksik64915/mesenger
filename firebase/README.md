# Хмара Гомона — Firebase

Тут лежить усе, що потрібно налаштувати в проєкті Firebase:
правила доступу до бази й функція, яка надсилає пуш.

```
firestore.rules          хто що може читати й писати — обовʼязково
firestore.indexes.json   індекси (їх не треба — файл для повноти)
firebase.json            конфігурація firebase CLI
functions/index.js       пуш через FCM на нове повідомлення
```

## Навіщо хмара

Без неї Гомін працює напряму між пристроями: швидко й без
сервера, але акаунт живе на одному телефоні, а повідомлення
доходять, лише поки обидва в мережі.

З хмарою:

* **один акаунт на кількох пристроях.** Раніше другий пристрій
  діставав відмову «юзернейм уже в мережі» — тепер до мережевого
  імені додається позначка пристрою, і телефон та компʼютер
  працюють одночасно;
* **повідомлення доходять офлайн.** Вони лежать у Firestore і
  зʼявляються в співрозмовника миттєво, щойно він відкриє
  застосунок;
* **юзернейми справді унікальні** — їх видає таблиця `usernames`,
  а не здогадка «хтось зараз у мережі»;
* **пуш через FCM.**

Дзвінки й далі йдуть напряму (WebRTC) — через хмару проходить
тільки сигнал про те, на який пристрій дзвонити.

## Що бачить власник проєкту

Профілі, списки чатів і **текст повідомлень** — як у будь-якому
месенджері із сервером. Медіа теж, якщо воно вміщається в
документ. Кому цього не треба — просто не вмикайте хмару:
прямий звʼязок працює як раніше.

## Налаштування (10 хвилин)

1. [console.firebase.google.com](https://console.firebase.google.com)
   → **Add project**.
2. **Build → Authentication → Get started → Email/Password →
   Enable.** (Пароль до Firebase не потрапляє: застосунок надсилає
   туди необоротну похідну SHA-256 від пароля й юзернейма.)
3. **Build → Firestore Database → Create database** → регіон
   ближче до вас → почніть у *production mode*.
4. **Firestore → Rules** → вставте вміст `firestore.rules` →
   **Publish**. Без цього кроку базу зможе прочитати будь-хто.
5. **Project settings → General → Your apps → Web (`</>`)** →
   зареєструйте застосунок → скопіюйте блок `firebaseConfig`.
6. Вставте його в `firebase-config.js` у корені проєкту **або**
   просто в застосунку: **Налаштування → Хмара → Підключити
   Firebase**.
7. **Налаштування → Хмара → Підключити цей акаунт до хмари** —
   і той самий @юзернейм із паролем працює на будь-якому
   пристрої (кнопка «Увійти в акаунт із хмари» на екрані входу).

### Пуш через FCM (необовʼязково)

8. **Project settings → Cloud Messaging → Web Push certificates →
   Generate key pair** → ключ у поле `vapidKey`.
9. Розгорніть функцію:

```bash
npm install -g firebase-tools
firebase login
cd firebase && firebase use --add
(cd functions && npm install)
firebase deploy --only functions
```

10. У застосунку: **Налаштування → Сповіщення → Пуш коли
    застосунок закритий → Увімкнути пуш через Firebase**.

Cloud Functions вимагають тарифу Blaze (є безкоштовна квота).
Якщо переходити на нього не хочеться — у теці `push-relay`
лежить той самий пуш через власний маленький сервер, і працює
він на безкоштовному плані Firebase.

## Як влаштовані дані

```
usernames/{юзернейм}         { uid }
users/{uid}                  { username, name, bio, avatar, seen,
                               peers:{пристрій:{id,ts}}, push }
users/{uid}/devices/{devId}  { fcm, seen, ua }      ← приватне
chats/{uidA__uidB}           { members[2], friend, reqFrom,
                               updated, last, reads:{uid:ts} }
chats/{…}/msgs/{msgId}       { from, type, text, ts, dur, wave, media }
```

`msgId` — той самий ідентифікатор, що й на пристрої, тож
повідомлення, яке прийшло і напряму, і з хмари, не подвоюється.
Фото й голосові лежать у полі `media` (обмеження документа
Firestore — 1 МБ; більше застосунок надсилає лише напряму).

## Скільки це коштує

Безкоштовного плану Spark вистачає для кількох людей: 50 тис.
читань і 20 тис. записів на день, 1 ГБ у базі. Пуш через FCM
безкоштовний, платні тут лише Cloud Functions (тариф Blaze).
