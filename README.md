# Гомін — PWA

Месенджер із прямим звʼязком між пристроями: повідомлення, фото, голосові,
аудіо- та відеодзвінки, акаунти з паролем.

Це прогресивний вебзастосунок: встановлюється на телефон з іконкою на
робочому столі, запускається на весь екран без адресного рядка й
відкривається без мережі.

```
index.html             весь застосунок (стилі та код усередині)
firebase-config.js     дані вашого проєкту Firebase (порожні = без хмари)
manifest.webmanifest   назва, іконки, колір, ярлики
sw.js                  service worker: офлайн-кеш, оновлення, пуш
icons/                 192, 512, maskable 512, apple-touch, favicon
firebase/              правила Firestore і функція пушу (FCM)
push-relay/            необовʼязковий сервер пуш-сповіщень (Node)
.github/workflows/     автоматична публікація на GitHub Pages
```

---

## Дві бази даних

**На пристрої — IndexedDB.** Там лежать усі ваші чати, зашифровані
паролем акаунта. Працює завжди, навіть без мережі й без хмари.

**У хмарі — Firestore.** Необовʼязкова, вмикається за пʼять хвилин
і дає те, чого прямий звʼязок дати не може: акаунт на кількох
пристроях, повідомлення для того, хто зараз офлайн, і пуш.

| | тільки пристрій | + хмара |
|---|---|---|
| Листування, дзвінки, медіа | так | так |
| Один акаунт на кількох пристроях | ні | так |
| Повідомлення офлайновому другові | чекає в черзі | доходить одразу |
| Пошук за юзернеймом | лише хто зараз у мережі | будь-хто |
| Хто бачить листування | ніхто, крім вас двох | ще й власник проєкту Firebase |

Налаштування хмари — у [`firebase/README.md`](firebase/README.md),
коротко: створити проєкт → увімкнути Email/Password → створити
Firestore → вставити `firestore.rules` → скопіювати
`firebaseConfig` у `firebase-config.js` (або просто в застосунку:
**Налаштування → Хмара**).

### Один акаунт на двох пристроях

Раніше другий пристрій діставав «юзернейм уже в мережі» й лишався
без звʼязку: імʼя в мережі збігалося з юзернеймом, а зайняти його
могли тільки раз. Тепер імʼя займає той, хто прийшов першим, а
наступні пристрої беруть `homin-<юзернейм>-<пристрій>` і працюють
одночасно. Для співрозмовника нічого не змінюється — чат
лишається тим самим, а куди саме стукати, підказує список
пристроїв із хмари.

На новому пристрої: **«Увійти в акаунт із хмари»** на екрані
входу — той самий @юзернейм і пароль.

Пароль у Firebase не потрапляє: туди йде необоротна похідна
SHA-256 від пароля й юзернейма, а ключ, яким шифрується база на
пристрої, рахується окремо (PBKDF2) і телефон не залишає.

## База даних

Чати, повідомлення, фото, голосові й журнал дзвінків лежать у
**IndexedDB** — базі даних усередині браузера. Кожен запис
зашифрований тим самим ключем, що походить від пароля акаунта; у
відкритому вигляді лишаються тільки поля для пошуку: акаунт, чат
і час.

```
profile    профіль власника акаунта
chats      імʼя, аватар, прапорці, лічильник непрочитаних
messages   повідомлення (індекс: чат + час)
media      фото й голосові — окремо від тексту
calls      журнал дзвінків
kv         дрібниці: адреса підписки на пуш
```

Що це дає:

* **історія не обрізається.** Раніше все листування було одним
  рядком у localStorage: понад ~5 МБ туди не вміщалося, тому
  зберігалися лише останні 160 повідомлень на чат, а фото й
  голосові викидалися першими. Тепер місця — сотні мегабайтів;
* **швидкий запуск.** На старті піднімаються тільки хвости
  розмов, а повна історія й медіа — коли чат відкривають;
* **менше памʼяті.** Медіа інших чатів вивільняється, лишаючись
  на диску.

Стан бази видно в **Налаштування → Дані → Сховище**: скільки
повідомлень і медіа збережено та скільки місця зайнято. Там же —
кнопка «Захистити від автоочищення»: браузер обіцяє не витирати
дані, коли на пристрої закінчується місце.

Старі акаунти переносяться самі: під час першого входу дані
розшифровуються зі старого сховища, лягають у базу, а зайвий
рядок у localStorage прибирається. Якщо IndexedDB недоступна
(деякі приватні вікна), застосунок непомітно повертається до
старого способу зберігання.

## Сповіщення

**Поки застосунок запущений** — навіть згорнутий у фон — нові
повідомлення, запити в друзі та дзвінки показуються системними
сповіщеннями; на іконці зʼявляється лічильник непрочитаних.
Увімкнути: **Налаштування → Сповіщення**. Приглушені чати
(«Вимкнути сповіщення» в меню чату) мовчать, а текст у сповіщенні
можна сховати, лишивши тільки імʼя відправника.

**Коли застосунок закрито**, прямого звʼязку немає — розбудити
пристрій може лише push-служба браузера. Для цього є два шляхи,
обидва вмикаються в **Налаштування → Сповіщення → «Пуш коли
застосунок закритий»**:

* **свій ретранслятор** — теку [`push-relay/`](push-relay/)
  запускають трьома командами, і працює він на безкоштовному
  плані Firebase (або взагалі без нього);
* **FCM** — якщо хмару вже підключено: розгорніть функцію з
  [`firebase/functions`](firebase/functions) і вкажіть `vapidKey`.
  Cloud Functions потребують тарифу Blaze.

Гомін сам передасть свою адресу підписки друзям через уже
наявне зʼєднання. Далі, коли друг пише вам, а ваш застосунок
закритий, його Гомін стукає у **ваш** ретранслятор — і телефон
дзвонить. Ретранслятор бачить лише те, що вам щось надійшло і від
кого; текст, фото, голосові та дзвінки через нього не проходять.

На iPhone сповіщення працюють лише у **встановленому** застосунку
(«На екран «Додому», iOS 16.4+), у вкладці Safari — ні.

## Важливо: потрібен https

Service worker, камера й мікрофон працюють лише на `https://` або на
`http://localhost`. Якщо просто відкрити `index.html` подвійним кліком
(`file://`), встановлення й офлайн-режим не запрацюють. Тому застосунок
треба десь розмістити — нижче три способи, від найпростішого.

## Спосіб 1 — GitHub Pages (безкоштовно, автоматично)

1. Створіть репозиторій на GitHub.
2. Завантажте туди **вміст цієї теки** (`index.html` має опинитися в корені,
   не в підтеці). Кнопка **Add file → Upload files**, перетягніть усе разом
   із прихованою текою `.github`.
3. **Settings → Pages → Source: GitHub Actions**.
4. Вкладка **Actions** покаже запуск «Deploy PWA to GitHub Pages». За хвилину
   сайт буде за адресою `https://<логін>.github.io/<репозиторій>/`.
5. Відкрийте цю адресу на телефоні → меню браузера → **«Встановити застосунок»**.

## Спосіб 2 — Netlify Drop (без реєстрації репозиторію)

Відкрийте [app.netlify.com/drop](https://app.netlify.com/drop) і перетягніть
туди цю теку. Через кілька секунд отримаєте посилання виду
`https://щось.netlify.app` — воно вже з https і одразу готове до встановлення.

## Спосіб 3 — локальна перевірка

```bash
python3 -m http.server 8080
```
і відкрийте `http://localhost:8080` — на localhost браузер дозволяє і service
worker, і доступ до камери з мікрофоном.

## Як встановити на телефон

**Android (Chrome, Edge, Samsung Internet).** Відкрийте адресу → меню (⋮) →
«Встановити застосунок» або «Додати на головний екран». Застосунок також
пропонує це сам: **Налаштування → Застосунок → Встановити застосунок**.

**iPhone (Safari).** Кнопка «Поділитися» → «На екран «Додому» → «Додати».
Safari не показує автоматичної пропозиції — у налаштуваннях застосунку є
підказка з кроками.

**Компʼютер (Chrome, Edge).** Іконка встановлення в адресному рядку праворуч.

## Оновлення

Замінили `index.html` — застосунок сам помітить нову версію при наступному
запуску й покаже внизу «Доступна нова версія → Оновити». Вручну:
**Налаштування → Застосунок → Перевірити оновлення**.

Якщо змінюєте файли, підніміть номер у першому рядку `sw.js`:

```js
const VERSION = 'homin-v1.5.0';   // → 'homin-v1.5.1'
```

Інакше старий кеш може лишитися в декого з користувачів.

## Що працює офлайн

Сам застосунок, усі ваші чати, медіа й налаштування — вони зберігаються на
пристрої в зашифрованій базі даних. Не працює офлайн лише те, для чого
потрібен співрозмовник: надсилання повідомлень (вони стануть у чергу й підуть
самі, щойно зʼявиться мережа) і дзвінки.
